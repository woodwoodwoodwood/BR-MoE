# A100：全 INT3 优化与 FP16 同卡对照

日期：2026-09-26。本轮覆盖 attention、共享专家和 routed experts 均为 INT3 的模型，以及原生 FP16 模型。所有性能数字来自 A100 本轮实测，不使用 5090 的加速比推算。

## 测量条件

- NVIDIA A100 80GB PCIe，300 W；驱动 570.133.20；PyTorch 2.13.0+cu129、Triton 3.7.1、CUDA 12.9。
- vLLM 源码版本 `27a94d1ce4e3fc100c4732439ccec10f8246a804`，运行时版本 `v0.1.dev1+g27a94d1ce`。
- TP=1；128 输入 / 128 输出；batch 1/2/4/8/16/32/64/128；CUDA Graph；prefix cache 关闭；每档重复 3 次取中位数。
- TTFT 是独立的单输出 token 请求墙钟；TPOT=`(E2E−TTFT)/127`。初始化、权重加载与 graph capture 不计入这些指标。
- 同 batch 内重复相同 prompt、greedy decode；使用同一个修复后的 tokenizer 和 `max_num_batched_tokens=2048`。
- FP16 使用本次 vLLM 自动选择的 Triton unquantized MoE；日志提示缺少 `E=64,N=1408,device_name=NVIDIA_A100_80GB_PCIe.json`，采用内置默认 MoE 配置，未额外调优 FP16。这是当前部署基线，不是 FP16 性能上限。attention backend 为 FlashAttention 2；INT3 保留 FP16 activation 与 KV cache。
- FP16 checkpoint：`/mnt/4090/data/jianglei/models/DeepSeek/deepseek-moe-16b-base`。
- 全 INT3 checkpoint：`/mnt/709/data3/home/jianglei/models/brmoe-3bit-vllm-int3dense`。这里的目录名对应全 INT3 模型。

## 从 5090 移植时重新检查的内容

1. 重跑 A100 原线性层、MoE 外围融合与单权重 Tensor Core 组合的端到端对照。
2. job 39246 重新采集 A100 batch 8/16/32/64/128 的 112 层真实线性输入和 27 层真实专家路由，保存 584 个线性样本和 135 个 routed MoE 样本。每档为最后一次观测到的 decode 调用，并非完整路由轨迹。
3. job 39248 使用全部 112 层比较单 slot、BK64/BK128、BN32/BN64；每组同时测量完整 shared+routed MoE。大 M prefill 使用 6 个代表投影单独对照。
4. 重新比较小 M GEMV 与专用 TC。小 M 初筛切片使用真实 M8 的输入行；最终收益以目标 batch 的真实请求端到端结果确认。
5. 正式自动分派接入后再次验证数值、CUDA Graph 与端到端；分阶段事件采样使用独立引擎。

此前排队的融合作业 39144 已完成：M4/8/16/32 的 TPOT 从 8.274/12.211/11.964/16.224 ms 降到 6.518/9.533/8.357/12.825 ms，23,040 个输出 token ID 一致。它使用当时冻结的旧线性代码，作为历史证据保留，不与下方新版本数据混成一组。

## 最终线性层分派

| 条件 | A100（sm_80） | 5090（sm_120） |
|---|---|---|
| auto / FP16 / GS64，小 M | M≤2：原 split-K GEMV | M≤8：原 split-K GEMV |
| auto，中小 M | 3≤M≤128：专用 TC | 9≤M≤128：专用 TC |
| TC 配置 | BM/BN/BK=32/64/128，4 warps，3 stages | 相同 |
| auto，M>128 | 原 GEMM，slot=BM=64，BK32 | 相同 |
| legacy 或其他架构 / GS / dtype | 原分派 | 原分派 |

M≤16 时专用 TC 的 BM 为 16。M 为实际调用行数，包含 graph padding / prefill 调度的影响。`BRMOE_LINEAR_BACKEND=auto` 为默认；复现完整优化组合还需 `BRMOE_CUDA_FUSE=1`。`BRMOE_GROUPED_GEMV=0`、`BRMOE_MOE_SMEM=legacy`，本轮不启用此前未通过端到端验收的资源限制实验。

小 M 初筛（39251，112 层合计 ms）：

| M | 原 GEMV | 专用 TC BK128 |
|---:|---:|---:|
| 1 | 1.649 | 2.714 |
| 2 | 2.251 | 2.715 |
| 4 | 3.581 | 2.717 |
| 8 | 6.251 | 2.719 |

因此 A100 阈值从 8 调至 2。BK64、BN32 或固定 BM16 没有形成更好的全层配置；大 M prefill 的 TC BK128 也不及单 slot BK32，因此未统一使用专用 kernel。

## 最终端到端：FP16 / 旧全 INT3 / 完整优化

**job 39253，同一张 A100 上三个独立进程依次运行；production 使用正式 auto 分派，无线性调参 hook。**

| batch | FP16 TPOT ms | INT3 unfused TPOT ms | INT3 最终 TPOT ms | FP16 / 最终 TPOT |
|---:|---:|---:|---:|---:|
| 1 | 4.939 | 4.217 | **4.210** | 1.173× |
| 2 | 6.668 | 5.819 | **5.825** | 1.145× |
| 4 | 5.584 | 8.235 | **5.445** | 1.025× |
| 8 | 5.555 | 12.224 | **5.766** | 0.963× |
| 16 | 6.037 | 11.880 | **6.397** | 0.944× |
| 32 | 9.179 | 16.211 | **7.533** | 1.218× |
| 64 | 12.188 | 24.427 | **10.509** | 1.160× |
| 128 | 18.232 | 32.675 | **17.882** | 1.020× |

比值 >1 表示最终 INT3 的 decode 更快。bs8/16 仍比当前 FP16 基线慢约 3.8% / 6.0%；bs128 的 decode 优势约 1.9%，不应外推为普遍优势。相对旧全 INT3，bs64 的 TPOT 降幅约 57.0%。

| batch | TTFT FP16 → 最终 INT3 ms | 完整请求 E2E FP16 → 最终 INT3 ms |
|---:|---:|---:|
| 1 | 25.22 → 18.43 | 652.44 → 553.07 |
| 2 | 27.21 → 27.28 | 873.99 → 767.03 |
| 4 | 34.21 → 45.86 | 743.35 → 737.41 |
| 8 | 50.49 → 86.51 | 756.00 → 818.74 |
| 16 | 87.14 → 159.41 | 853.87 → 971.85 |
| 32 | 172.16 → 314.65 | 1337.93 → 1271.41 |
| 64 | 341.04 → 627.01 | 1888.94 → 1961.68 |
| 128 | 680.79 → 1254.19 | 2996.27 → 3525.17 |

**完整请求并未全面超过 FP16。** bs32 的 E2E 从 FP16 的 1337.93 ms 降到 1271.41 ms；bs64/128 则分别慢约 3.9% / 17.7%。bs≥4 的 TTFT 仍落后，尤其 bs128 为 1254.19 ms，对应 FP16 为 680.79 ms。相对旧全 INT3，bs128 TTFT 已从 1878.53 ms 降低约 33.2%。

权重、quantization 和 tokenizer 配置在 INT3 三组之间保持一致。本轮保留 FP16 / INT3 各自生成的实际路由，不用 FP16 的路由替代量化模型路由。

## 正式路径的完整算子回放

job 39252，在同一 GPU 固定使用 A100 采集的输入、expert IDs 和路由权重。两侧均开启 MoE 外围融合，只比较线性层改动。单位 ms：

| M | 112 个线性投影 legacy → auto | 27 层完整 shared+routed MoE legacy → auto |
|---:|---:|---:|
| 8 | 6.246 → **2.719** | 4.825 → **3.154** |
| 16 | 5.463 → **2.716** | 4.823 → **3.373** |
| 32 | 9.262 → **2.680** | 7.816 → **4.657** |
| 64 | 17.157 → **3.338** | 12.912 → **6.294** |
| 128 | 18.205 → **5.559** | 15.978 → **10.042** |

完整 MoE 包括共享 gate_up、SiLU×up、shared down、routed MoE 和两分支相加；gate/top-k 使用已采集结果。回放按顺序计算两分支，端到端的 vLLM 可以重叠执行，两个范围不能直接互换。

M2048 的 6 个代表投影：**12.387 → 4.658 ms**。这不是 112 层总时间，也不是整模型 TTFT。

## 算子调用逻辑

[离线 HTML](brmoe-kernel-paths.html)包含五张可缩放、可下载的图。第 4 张描述 INT3 kernel 的 tile 与解码过程，第 5 张描述模块调用：

- **attention**：input RMSNorm 输出 → INT3 QKV（2048→6144）→ split 视图 → RoPE(Q,K) → FP16 attention / KV cache → INT3 O（2048→2048）。
- **共享专家**：MoE 输入 → INT3 gate_up（2048→5632）→ SiLU×up（输出 2816）→ INT3 down（2816→2048）→ 与 routed 输出相加。
- 两个共享专家合并为 I=2816 的 MLP；不通过 top-k 选择。vLLM runner 负责执行共享分支、同步和相加，量化 MoE 插件只返回 routed 分支结果。
- 共享分支可由 vLLM 在辅助 CUDA stream 上执行；禁用 stream、超出阈值或配置不允许重叠时采用 NO_OVERLAP。具体选择由本轮 profile 记录。
- 四种 INT3 投影都通过 `BRMoEInt3LinearMethod.apply → brmoe_int3::linear → _brmoe_int3_linear_impl`；112 个投影还包括首层 MLP 的 2 次线性运算。

[Attention / shared 独立 SVG](brmoe-attn-shared.svg)。图中的框表示模块/算子依赖，不等价于一次 GPU kernel launch。

## 复现

```bash
# 同一 GPU 上依次跑 FP16、原全 INT3、最终全 INT3；每个 case 使用独立引擎。
CASES='fp16 unfused production' sbatch --export=ALL bench/a100_full_int3_study.slurm

# 重新采集 A100 真实路由与线性输入，随后做初始单 slot 对照。
PHASE=collect sbatch -p a100 --export=ALL bench/int3_linear_study.slurm

# 使用上一步 run 目录；固定同一份输入/路由，测完整算子并验证数值。
PHASE=compare ARGS='--input /absolute/path/to/run_capture --configs baseline,production --prefill' \
  sbatch -p a100 --export=ALL bench/int3_linear_study.slurm

# 独立分阶段采样，包含实际 shared expert stream 选择。
PHASE=profile ARGS='--linear-config production --batch-sizes 8,16,32,64,128' \
  sbatch -p a100 --export=ALL bench/int3_linear_study.slurm
```

`bench/a100_full_int3_study.py` 对每个 case 保存实际源文件和 CUDA 扩展 SHA256、软件版本、环境开关、计时与输出 token IDs。`unfused` 固定为 legacy 线性层且 MoE fusion 关闭；`fused` 固定为 legacy 线性层且 fusion 开启；`production` 使用正式 auto 线性分派并开启 MoE fusion。FP16 与量化模型不要求生成结果相同；输出 token 对照用于检查 INT3 优化前后。
