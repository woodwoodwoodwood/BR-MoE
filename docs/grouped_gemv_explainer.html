03 / ROUTE → EXPERT GROUP

只重新组织路由索引，输入 x 不做全量搬运

教学例子使用 4 个 token、topk=2、3 个专家。颜色表示专家；r 是原始 route ID，t 是 token ID。示例不代表实际模型的路由分布。

原始 token / top-k 顺序

route = token × topk + topk_slot key = expert × TOTAL + route TOTAL = M × topk = 8

x 仍然按 token 顺序存储。GPU 只对整数 key 排序，然后识别专家边界和小组起点。

排序后的专家小组

共享的粒度是「同一个专家小组 × 同一个 N tile × 同一个 K 分段」。不同专家不会共用同一份权重；不同输出 tile、split-K 段也会分别加载对应权重。
展开：分组元数据的含义

SORTED 存排序后的 key；STARTS 存每组在 SORTED 中的起点；EXPERTS 存每组专家编号；COUNT 存有效组数。组尾不足 ROWS 的位置由掩码屏蔽，不会跨到下一个专家参与计算。灰色槽位仅用于示意掩码，没有额外分配 padding 行。

04 / INSIDE ONE TILE

一次解包，供同组多个 token 使用

① 从 3 个 uint32 恢复 32 个 INT3 值

本实现采用 BR-MoE 的打包方式。每个 32-bit word 有两段：各存 4 个 3-bit 值与 4 个用于拼接的 bit。

↓ 拼接散落的 4-bit 片段
w3：寄存器中恢复的虚拟 word
收集 w0 / w1 / w2 的 bit 12–15 和 bit 28–31，拼出剩余 8 个 INT3 值；不额外读取第 4 个全局内存 word。
q = (selected_word >> shift) & 7 b = (q.to(fp16) − zero) × scale
真实模型使用按量化组的浮点 scale / zero。GROUPS=1 表示每轮处理 32 个 K 值；量化 group_size=64，二者不是同一个参数。

② 广播权重块，归约 K 维

一份 b
[32, BLOCK_N]
同一专家的反量化权重
→
token / route 0 的 a
token / route 1 的 a
… 同组 ROWS 行
a: [ROWS, GROUPS, 32] b: [GROUPS, 32, BLOCK_N] prod = fp32(a[..., None]) × fp32(b[None, ...]) acc += sum(prod, K维) acc: [ROWS, BLOCK_N] / FP32

这里用 tl.sum 与浮点乘加 实现 GEMV，没有调用 tl.dot / Tensor Core MMA。减少重复解包可以提速，但不能直接按 16÷3 推导整个算子的加速比。

实现同时支持 K-major 与 N-major；当前插件将权重转为 K-major，使相邻输出通道的打包权重在内存中连续。
05 / PARALLELISM & REDUCTION

split-K 分摊长循环，persistent CTA 消化有效任务

任务坐标如何映射？

有效任务数 = COUNT × ceil(N / BLOCK_N) × KSPLIT group_id = tile % COUNT n_tile = (tile // COUNT) % tiles_n k_split = tile // (COUNT × tiles_n) for tile = CTA_id; tile < 有效任务数; tile += CTA数: _grouped_tile(group_id, n_tile, k_split)
启动 CTA 数：min(TOTAL × tiles_n × KSPLIT, SM 数 × 4)。COUNT 在 GPU 上读取，无需传回 CPU 才能决定下一步；每个 CTA 可连续处理多个 tile。这不是动态工作窃取队列。

两个阶段，写回地址不同

w13 · ADD=Falseatomic_add(inter[route, n], partial)不同 K 分段累加到原 route 行的 FP32 中间结果。
w2 · ADD=Trueatomic_add(out[token, n], partial × route_weight)同时归约 split-K 和 top-k 专家贡献，输出回到原 token 顺序。
两次 GEMV 之间由独立 SiLU kernel 隔开：前一级全部完成后，才读取最终 inter。不能先对每个 split 的 partial 独立做 SiLU，因为 SiLU 是非线性函数。

CUDA Graph 为什么可以回放？

  • 所有缓冲按静态形状缓存，热身时建立工作区。
  • COUNT、路由排序与分组始终留在设备上。
  • 每次 replay 重新分组、清零，再计算；不会复用上次的路由值。
  • workspace 沿用原算子的单流使用约定；不支持多个并发流随意共用同一缓冲。
export BRMOE_GROUPED_GEMV=1
当前生产入口只为 sm_120 的 M=4–16 启用此实验路径。CUDA Graph 复用的是执行图，数据仍可在每次回放时变化。
